## Codex 를 뺀 까닭 (R3 (a))

이 데이터 (TabArena 판, 7,491행) 에는 (피처, 타깃) 이 같은 중복이 하나도 없고, 86열 꼴이 같은 행 96쌍은 모두 **타깃이 반대** 인 두 행 (중복을 뺀 흔적, 누가 뺐는지는 확인 못 함).
그래서 r0f0 test 중 42행은 꼴이 같은 train 행이 있고 정답은 그 행의 반대 (42행 모두), 28행은 test 안에 같은 꼴 짝이 있고 짝끼리 타깃이 반대.

- Codex 의 최종 제출은 두 묶음을 **후처리로 배정**: 42행 = `1 − (같은 꼴 train 행의 레이블)` (0 / 1), 28행 = 0.5 (`score.py` 의 `correct`, 최종 명령 `codex.jsonl` 의 240번째 명령). 28행은 test 행끼리 견준 것이라 TabArena 의 inductive 규칙 밖
- 같은 배정을 우리 kumo 예측에 하면 0.00840 (Codex 0.00855 보다 나음). 70행을 빼면 Codex 0.00795 · kumo 0.00781 → Codex 가 FM 보다 나은 몫은 모두 배정. MLE-bench leaf × Codex (분할 구조 배정) 를 뺀 것과 같은 꼴
- AIDE × Sonnet 도 같은 구조를 씀 (42행 안 AUC 1.0) 이지만 **타깃 의존 피처로** (꼴 타깃 인코딩 · 이웃 레이블 평균, 아래) 배운 것이라 R3 (a) (배정 후처리) 로 보지 않고, 그 블록만 규칙 3 으로 F2 에서 뺌. 타깃 비의존 블록 7열이 남아 R3 (c) 도 해당 없음. AIDE 도 70행을 빼면 0.00975 (kumo 0.00781 보다 나쁨)

## F2 후보와 뺄 것

- `~f2` = F0 (범주 86) + 개수 3 + `pfreq` + `nn1`·`nn2`·`nn4` = **93 열**
- train 판 (R3 해석): `pfreq` = 자기 + train 의 같은 꼴 수 (test 행도 자기를 셈 → train 에 없는 꼴 1, train 에 짝이 있는 42행 2), `nn*` = train 행 중 거리 안의 다른 행 수 (train 행은 자기를 뺌). 개수 3열은 그대로
- 뺄 것: `pte`·`b2_te`·`b4_te` (타깃 의존, 규칙 3. 이 실행이 구조를 배운 곳), `pcnt`·`b2_c`·`b4_c` (위 train 판과 같은 양), 모델 · seed · base/ball 고르기 (OOF 정답으로 고름)
- **해석 주의**: `pfreq = 2` · `nn1 ≥ 1` 은 "꼴이 같은 짝이 train 에 있음" 을 레이블 없이 알려 줌. train 에서 그런 행은 짝과 타깃이 반대라 모델이 애매하게 둠 → test 42행에도 같은 신호가 들어감 (inductive 안, 타깃 비의존이지만 데이터 구조의 신호)

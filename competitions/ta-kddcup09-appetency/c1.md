## F2 후보와 뺄 것

- `~f2` = F0 (수치 174 + 범주 38) + **범주 값 빈도 38** = 250 열. 빈도는 에이전트가 train+test 로 셈 → R3 해석대로 **train 행으로만** 다시 셈 (test 에만 있는 값은 0, 결측은 train 의 결측 수)
- 뺄 것:
  - 타깃 인코딩 38 열: 타깃 의존 (규칙 3). LGB·XGB 의 범주 정보는 이것과 빈도뿐이라 이 실행의 범주 처리 이득 중 꽤 큰 몫이 여기 있을 수 있음 (나눠 재지 않음)
  - 블렌드 무게 (OOF 정답으로 고름), seed 평균, fold 평균: 모델 쪽
  - 범주 코드 (TE 키): 모델 입력이 아님
- **R3 판정**: (a) 외부 정보·할당 없음 (b) 최종에 원본 밖 블록 (빈도 · TE) 있음 → 해당 없음 (c) 타깃 비의존 블록은 빈도 38 뿐이고 train+test fit → train 으로만 다시 fit 해 후보로 둠 (R3 해석, 아니면 (c) 로 Codex × GPT 0.1569 로 내려감)
- 해석 주의: F2 는 빈도 38 열만 더하는 얇은 블록. 우리 kumo (`kumo_cat_refit`) 는 범주 값이 50개 이상이면 이미 빈도 열을 스스로 만듦 ("FM 이 TabArena 와 맞는지" 의 "kddcup09") → kumo 에는 겹치는 정보일 수 있음. 에이전트 노드 CV 0.8477 은 무게를 같은 OOF 로 고른 값이라 낙관적

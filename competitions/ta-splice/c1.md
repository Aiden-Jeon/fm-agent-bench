## F2 후보와 뺄 것

- `~f2s` = A + B + C (행 단위 원-핫·개수). 열 수 수천 (build 후 셈). 어휘·레벨은 train 행만으로 다시 fit 해야 inductive 안 → 그때 F2 후보로 인정
- `~f2` = `~f2s` + D + E. 5만 열을 넘음 → TFM 상한 (roadmap 규칙 6) 대상. 큰 열 수 때문에 GBDT·FM 결과가 상한 적용 방식에 많이 달라질 수 있음
- 뺄 것 (타깃 의존 또는 모델 쪽):
  - T1. 클래스별 생성 모델 (`generative.py`, `pairgen.py`, `wordgen*.py`, `wordprior`/`wordposprior`, `skipgen.py`, `backoff.py`, `codongen.py`): 클래스별 빈도로 확률을 씀 → 타깃 의존 (1차 규칙 밖). 모델 쪽
  - T2. OOF 생성 예측을 입력으로 쓰는 `jointgen.py:5-6`, `gatedgen.py:5-8`, `neural2.py:10-12` (neurrepeat·neurlong·neuralcodon 도 같은 틀): OOF 쌓기 → 2차 또는 모델 쪽
  - T3. 정답 이웃 치환 (`submit_final.py:13-22`): train 과 일치 위치 ≥ 34/60 인 테스트 행을 train 정답 투표로 섞음 (`votes`, `lvotes`, `support`; 이 행 수는 로그에 없음). 타깃 의존. nomad 의 "정답 섞기" 와 같은 계열 (roadmap C1 뺄 것). 점수 몫은 있으나 피처 블록과 섞여 있어 R3 (a) 로 빼지 않음
  - T4. 섞기 무게 (`meta_eval.py` 의 OOF 최적화로 정한 값) 와 신경망 0.2: 모델 쪽
  - T5. 애매한 염기 보정: 행 1개만 제출에 반영 (위). 피처가 아니라 예측 쪽 보정. 정답은 안 씀 (가중치는 train 피처 개수)
  - T6. 의사 라벨 (`pseudoval.py`): 최종 체인에 없음 (확인)
- 해석 주의:
  - 최종 제출은 피처 블록 기반 성분 (무게 .36 의 몫) + 생성·신경·치환 성분. 피처 몫만 재려면 F2 를 GBDT·LR 에 넣어 F0 대비 봄
  - 문서 [docs/tabarena.md](../../docs/tabarena.md) 의 "풀이 읽기" (코돈 사라짐, 0.06012) 는 **바꾼 실행** 얘기. 이 원래 실행에는 코돈 생성 모델 (`codongen`) 이 `submit_final.py:7-8` 에서 섞임
  - `extended_trees.py` 는 조기 종료 eval_set 이 검증 fold 라서 그 CV 가 낙관적일 수 있음 (확인 안 함)
